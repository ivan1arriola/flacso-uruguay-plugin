## B-0049 · 2026-11-22 · Opciones huérfanas del admin: diagnóstico en el servidor y PR #104
- Actor: Claude Code · Tier: T1 (diagnóstico, Haiku) y T2 (arreglo, Sonnet) · Modelo: Haiku y Sonnet. Autorización explícita del dueño para usar `ssh servidor-flacso` y `wp-cli` "para averiguar más".
- Tarea / alcance: el dueño (administrador de WordPress) reportó que en `wp-admin` "han desaparecido opciones, quedaron huérfanas y no puedo acceder". Se buscó la causa en el código (Haiku, solo lectura) y en el servidor.
- Modo: lectura. Todo lo hecho por `ssh` fue de solo lectura, como el usuario `web5` (`sudo -n -u web5 wp ...`, porque `ubuntu` no lee `wp-config.php`): versión de WordPress, lista de plugins, usuarios por rol (solo ID y rol), capacidades del rol administrador y una reconstrucción del menú del admin para el usuario 23 con scripts temporales en `/tmp` que se borraron. No se cambió ninguna opción, plugin ni archivo del servidor. No se volcó el log ni `wp-config.php`.
- Resultado:
  - WordPress 7.1.5, PHP 8.3, plugin `flacso-uruguay-plugin` 8.0.0.1329 activo. Tres usuarios: un administrador (ID 23) y dos con el rol `gestion_web`. El administrador tiene 289 capacidades (incluidas `manage_options` y `activate_plugins`).
  - **Todas las pantallas registradas por el código estaban disponibles para el administrador.** El código desplegado coincidía con `main` (hashes iguales). Ningún PR de esta auditoría tocó registros de menú ni capacidades de administrador.
  - **Pantallas que el código enlaza pero no registra** (anteriores a nuestros cambios): `docentes_panel` y `docentes_lista` (el archivo `modules/docentes/includes/admin.php` no se carga desde hace tiempo; las personas se administran desde el menú nativo "Personas / Equipo"), `fc_oferta_options_page`, el submenú "Migraciones" (cuelga de `flacso-main-page`, que es un submenú de Páginas y no un menú de primer nivel) y los enlaces de pestañas viejas de la Portada (`flacso-main-page-eventos|info|novedades|posgrados|quienes`, solo en una vista heredada que no se renderiza).
  - **Causa más probable de "no puedo acceder":** la tarjeta "Docentes" del Resumen FLACSO enlazaba a `admin.php?page=docentes_panel` (`class-flacso-admin-panel.php:175`).
  - **Arreglo:** PR #104 (commit `164adb9`): la tarjeta abre `edit.php?post_type=docente`; test nuevo `tests/admin-panel-links-test.php` (falló antes). Mergeado a las 04:55:25 UTC (`30d42f4`); despliegue en verde; el servidor tiene el archivo idéntico a `main` y el enlace nuevo.
- Hallazgos: H-A07 (enlace roto a `docentes_panel`, parte visible): cerrado. Siguen abiertos el submenú huérfano "Migraciones", el archivo `modules/docentes/includes/admin.php` sin cargar y los enlaces de pestañas viejas de la Portada.
- Verificación: sha1 del archivo en el servidor contra `main`; lectura del enlace en el servidor. No se probó el clic en la interfaz (requiere sesión). La reconstrucción del menú desde `wp-cli` dispara un `wp_die` final del núcleo con `pagenow=index.php`; se interpretó como artefacto de ejecutar el admin desde la línea de comandos, no como una falla real, porque la lista de menús ya estaba completa.
